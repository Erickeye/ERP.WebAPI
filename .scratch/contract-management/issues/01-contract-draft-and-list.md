# 01: 合約單草稿與基本列表（後端）

**Spec:** `.scratch/contract-management/spec.md`

**What to build:** 有「合約單編輯」權限的人可以建立合約單草稿（供應商合約或客戶合約），編輯、刪除草稿，檢視單筆，並在列表看到合約單（預設依起日由新到舊、分頁）。這張包含新的資料表與部署腳本、合約單單據類型、操作紀錄，以及合約單頁面需要的供應商、客戶、公司選單。簽核、附件與進階篩選由後續 ticket 處理。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 新增合約單資料表（供應商、客戶、公司外鍵皆限制刪除；單號唯一索引）、實體模型、DbContext、資料庫專案，並在 `docs/sql/` 提供可重複執行的建表腳本
- [x] 新增單據類型「合約單」，沿用既有權限碼（檢視 3050、編輯 30500、刪除 30501），不新增權限碼
- [x] 新增合約單狀態列舉（草稿、簽核中、已核准、已退回、已作廢）與 ViewModel
- [x] 建立草稿時由序號服務產生單號
- [x] 類型與對象恰好一個：供應商合約須有供應商且無客戶，客戶合約須有客戶且無供應商
- [x] 必填（合約編號、簽約公司、對象、起訖日、合約總金額）與長度驗證，儲存草稿時即檢查
- [x] 合約總金額大於 0 且最多兩位小數；迄日不得早於起日；起訖日可為過去日期
- [x] 合約編號在非作廢單之間唯一（編輯排除自己、作廢單不佔用、不分類型），重複回明確訊息
- [x] 停用的供應商與簽約公司不可選；客戶只檢查存在；不做期間重疊檢查
- [x] 只有草稿可編輯與刪除（已退回可編輯，之後 ticket 送簽用）；其他狀態回含目前狀態的錯誤
- [x] 單筆檢視與基本列表（欄位、預設依起日由新到舊、分頁）；查無資料回「找不到資料」
- [x] 供應商、客戶、公司選單可供合約單頁面使用（供應商與公司排除已停用者）
- [x] 新增、編輯、刪除寫入既有操作紀錄
- [x] 新增合約單服務測試檔（記憶體庫、假使用者、假序號服務），覆蓋上述規則
- [x] 專案編譯與全部測試通過

### 完成記錄（01）

- 驗證：`dotnet test src/ERP.Tests/ERP.Tests.csproj` 全套 550 筆通過（含新增的 `ContractServiceTests` 69 筆）。因 Visual Studio 正在執行 `ERP.WebAPI` 而鎖住 `bin` 內的 dll，本次以 `-p:OutDir=<暫存資料夾>` 導出編譯輸出，沒有結束使用者的程序。
- 未在真實環境驗證：`docs/sql/合約單資料表.sql` 與 `ERP.DB` 專案的資料表（含 CHECK 限制、外鍵、索引）尚未在 SQL Server 執行；列表排序（含金額 decimal 排序，SQLite 不支援）與分頁在真實資料庫的行為。留給 ticket 07。
- 控制器的權限屬性（Index／Get 要「合約單檢視」、Add／Edit 要「合約單編輯」、Delete 要「合約單刪除」）與 `[Log]` 以讀程式確認，沒有自動測試。
- 選單：供應商 `_4060Supplier/GetSelect` 與公司 `_1080Company/GetSelect` 的權限新增「合約單編輯」「合約單檢視」，使合約單使用者不需要進貨單、領料單等權限也選得到；兩者原本就只列啟用中並可用 `includeId` 帶回已停用者。客戶選單 `Shared/GetCustomerSelect` 原本沒有權限限制，不需改。
- 假設（spec 未明說，已照字面實作）：合約單編輯與刪除不限建單人，有「合約單編輯」權限者可編輯他人的草稿（spec 把合約視為公司層級資料）；若要限縮為建單人，需另行決定。
- 偏離 Q22 字面的處理：編輯時維持原本的供應商或簽約公司（即使之後被停用）仍可儲存其他欄位，只有「改選」停用者才擋，送簽時再擋（比照出差單與領料單做法）。送簽時的重新驗證屬 ticket 03。
- 控制器的 `Index`、`Get` 目前掛「合約單檢視」權限；ticket 04 要讓簽核人沒有檢視權限也看得到待簽核的單，屆時需拿掉這個屬性，改由服務層限縮可見範圍。
- 新增 Swagger 分組：`ApiGroupType.Contract`（合約管理）與 `Program.cs` 的 `SwaggerGroupResolver` 對應 namespace 判斷。未在 Swagger UI 實際確認。
- 資料表與實體是手寫的（沒有資料庫可 scaffold），與 `t_4061SupplierPrice`、`t_1060BusinessTrip` 的 scaffold 風格一致；之後若重新 scaffold，請確認 `t_3050Contract` 的輸出與此一致。
- 供應商、公司與客戶的刪除引用保護由 ticket 05 處理，本 ticket 沒有改動它們的刪除檢查。
