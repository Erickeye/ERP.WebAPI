# 03: 送簽、核准、拒絕、撤銷、重送與作廢（後端）

**Spec:** `.scratch/contract-management/spec.md`

**What to build:** 合約單走簽核：建單人送簽，簽核人核准或拒絕，建單人可撤銷與重送已退回的單，最後一關簽核人可作廢已核准的單。五個簽核動作走合約單專屬端點，與單據狀態同一交易（依 `docs/attendance/adr/0001`），做法參考出差單。

**Blocked by:** 01、02

**Status:** resolved

- [x] 新增合約單簽核目標轉接器並手動註冊；通用簽核控制器擋下合約單的送簽、核准、拒絕、撤銷、作廢（簽核進度與「待我簽核」查詢不擋）
- [x] 狀態流轉：草稿 → 簽核中；簽核中 → 已核准（最後一關）／已退回（拒絕或撤銷）；已退回 → 簽核中；已核准 → 已作廢；已作廢為終態；中間關卡核准不改狀態
- [x] 前置狀態檢查在引擎動作之前，錯誤訊息包含目前狀態
- [x] 送簽時附件必填；送簽時重新驗證供應商與簽約公司未停用、對象存在
- [x] 沒有啟用的簽核設定或有多組啟用設定時，把引擎的錯誤原樣轉出
- [x] 供應商合約與客戶合約共用同一組簽核設定
- [x] 拒絕必須填原因；還沒輪到的簽核人無法核准
- [x] 簽核動作失敗時，簽核紀錄與合約單狀態一併回復
- [x] 只有最後一關簽核人可作廢，指定人員與指定角色兩種簽核模式都適用；作廢後不可重送
- [x] 已進入簽核中、已核准的單不受之後對象或公司停用影響
- [x] 五個動作寫入既有操作紀錄
- [x] 測試覆蓋上述規則（假簽核引擎，含狀態與簽核紀錄一併回復）
- [x] 專案編譯與全部測試通過

## Comments

### 完成記錄（03）

- 驗證：`dotnet test src/ERP.Tests/ERP.Tests.csproj` 全套 618 筆通過（`ContractServiceTests` 新增簽核動作測試，`ApprovalControllerGuardTests` 新增合約單的五個被擋案例）。編譯輸出仍以 `-p:OutDir=<暫存資料夾>` 導出，原因同 ticket 01。
- 用假引擎（`FakeApprovalWorkflowService`）驗證服務層的狀態流轉與交易回滾。「拒絕必填原因」「還沒輪到不能核准」「只有送簽人可撤銷」「只有最後一關簽核人可作廢（指定人員與指定角色兩種模式）」是引擎的行為，合約單服務只原樣轉出引擎錯誤，這些規則由既有的 `ApprovalWorkflowServiceTests`（真實引擎）與出差單前置修正涵蓋，本 ticket 沒有重測，也沒有用真實引擎驗證合約單。
- 「供應商合約與客戶合約共用同一組簽核設定」：兩者都以 `TableType.合約單` 送進引擎，沒有依合約類型區分；測試驗證兩種合約都能送簽，沒有驗證引擎端的設定查詢。
- 簽核動作的單據查找：以單號在全部合約單中找，沒有套用可見範圍（ticket 04 處理列表、單筆與下載的可見範圍）。送簽與撤銷的控制器要「合約單編輯」權限，核准、拒絕、作廢不加功能權限，由引擎依簽核紀錄判斷（比照出差單）。
- 送簽時的重新驗證：簽約公司已停用、供應商（供應商合約）已停用會被擋下；客戶沒有停用概念，只靠外鍵確保存在。
- 未做：`CanApprove`、`CanEdit`、`CanRevoke`、`CanVoid` 這類「目前使用者能做的動作」旗標不在本 ticket 驗收範圍，前端（ticket 06）需要，預計在 ticket 04 一併提供。
- 沒有在真實環境驗證：實際簽核流程（真實引擎、真實簽核設定）留給 ticket 07。
