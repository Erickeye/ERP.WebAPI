# 合約管理（合約單：供應商合約與客戶合約）

Status: ready-for-agent

相關文件：`GLOSSARY-MAP.md`（合約管理 context，術語以 `docs/contract/GLOSSARY.md` 為準：合約單、供應商合約、客戶合約、合約對象、簽約公司、合約編號、合約總金額、合約單狀態、生效中、已到期、作廢）。簽核單據的做法參考 `docs/attendance/adr/0001`（簽核動作與單據狀態同一交易、走專屬端點）與 `.scratch/business-trip/spec.md`（五個狀態、列表可見範圍、最後一關簽核人作廢）。供應商與公司的「被引用就只能停用」規則見 `docs/inventory/GLOSSARY.md` 與 `docs/company/GLOSSARY.md`。程式導覽與新增簽核單據的檢查清單見 `docs/agents/codebase-map.md`。

## Problem Statement

我方與供應商、客戶簽訂的合約目前沒有地方登錄與簽核：合約掃描檔散落在個人電腦或紙本，沒有統一的編號、期間與金額紀錄，無從查詢「這間供應商現在有哪些生效中的合約」，也沒有核准的軌跡。系統已預留「合約單」權限碼，但沒有任何對應的資料表與功能。

## Solution

提供**合約單**：有權限的人建立合約單，選擇**供應商合約**或**客戶合約**，指定**合約對象**、**簽約公司**、**合約編號**、起訖日期、**合約總金額**、選填備註，並上傳一份 PDF 掃描檔，送出簽核；全部簽核通過後為已核准。已核准的合約單內容不可修改，有誤或提前終止只能由最後一關簽核人**作廢**，需要時另開新單。

合約單有五個**合約單狀態**：草稿、簽核中、已核准、已退回、已作廢。「生效中」與「已到期」不儲存，由「已核准且今天落在起訖日內／晚於結束日」計算並在列表顯示。檢視權限可看全部合約單；簽核人另可在列表篩選「待我簽核」。

合約單不取代供應商報價，也不影響進貨單與庫存；本次不做明細行、付款條件、續約與到期提醒。

## User Stories

### 建立與編輯草稿

1. 身為合約建單人，我想新增一張合約單並選擇類型為供應商合約或客戶合約，以便登錄不同對象的合約。
2. 身為合約建單人，我想供應商合約只能選供應商、客戶合約只能選客戶，以便對象與類型一致。
3. 身為合約建單人，我想同一張合約單不能同時填供應商與客戶，也不能兩者皆空，以便對象恰好一個。
4. 身為合約建單人，我想選擇簽約公司，以便記錄代表我方簽約的公司。
5. 身為合約建單人，我想填寫合約編號，以便對應紙本合約。
6. 身為合約建單人，我想合約編號在非作廢的合約單之間不可重複，重複時被擋下並看到明確訊息，以便一份合約不會被登錄兩次。
7. 身為合約建單人，我想作廢單的合約編號可以被新單沿用，以便作廢重開不被舊單擋住。
8. 身為合約建單人，我想編輯草稿時修改合約編號但不與其他非作廢單重複，並排除自己，以便更正打錯的編號。
9. 身為合約建單人，我想填寫起日與迄日，以便記錄合約期間。
10. 身為合約建單人，我想結束日早於開始日時被擋下，以便期間合理。
11. 身為合約建單人，我想起訖日可以是過去的日期，以便補登已簽訂的舊合約。
12. 身為合約建單人，我想同一對象在同一簽約公司之下的合約期間可以重疊，以便框架合約與補充協議並存。
13. 身為合約建單人，我想填寫合約總金額，必須大於 0 且最多兩位小數，以便不存入零、負數或超出精度的金額。
14. 身為合約建單人，我想框架合約沒有固定金額時填預估金額，以便金額欄位一律有值。
15. 身為合約建單人，我想選填備註，以便記錄補充說明。
16. 身為合約建單人，我想儲存草稿時就檢查所有必填欄位與長度限制並看到明確訊息，以便不留下殘缺草稿。
17. 身為合約建單人，我想在草稿階段上傳一份 PDF 合約掃描檔，以便簽核人看到合約內容。
18. 身為合約建單人，我想上傳限定為 PDF 且不超過 10 MB，以便檔案格式與大小可控。
19. 身為合約建單人，我想在草稿或已退回時更換掃描檔，以便傳錯可以重傳。
20. 身為合約建單人，我想刪除草稿，以便清掉誤建的單；非草稿不能刪除。
21. 身為合約建單人，我想不能選已停用的供應商或已停用的簽約公司，以便新合約不會掛在已不使用的對象上。
22. 身為合約建單人，我想客戶沒有停用概念時任何客戶都可選，以便不被不存在的規則擋住。

### 送簽與撤銷

23. 身為合約建單人，我想把草稿送簽，以便讓簽核人決定是否核准。
24. 身為合約建單人，我想送簽時必須已上傳 PDF 掃描檔，以便簽核人有東西可看。
25. 身為合約建單人，我想送簽時重新檢查供應商與簽約公司未停用且對象存在，以便草稿放了幾天後對象被停用時被擋下並提示。
26. 身為合約建單人，我想已進入簽核中的合約單不受之後對象或公司停用的影響，以便簽核不會被中途打斷。
27. 身為合約建單人，我想在沒有啟用的簽核設定時送簽，被告知「找不到啟用中的簽核設定」，以便知道要請管理者先設定流程，單據不會卡在半路。
28. 身為合約建單人，我想同時有多組啟用的合約單簽核設定時送簽被擋下並提示設定重複，以便先修正設定。
29. 身為合約建單人，我想供應商合約與客戶合約共用同一組簽核設定，以便管理者只維護一組流程。
30. 身為合約建單人，我想在簽核完成前撤銷已送出的簽核，單據回到已退回，以便修改後重送。
31. 身為合約建單人，我想編輯已退回的合約單後重新送簽，以便處理簽核人的意見。
32. 身為合約建單人，我想合約單進入簽核中、已核准或已作廢後無法編輯、更換掃描檔或刪除，以便簽核後內容不被更動。
33. 身為合約建單人，我想已核准的合約若要修改內容或更換掃描檔，只能作廢後重開，以便核准過的內容不被悄悄改掉。

### 簽核

34. 身為簽核人，我想在列表篩選「待我簽核」，以便快速找到輪到我簽的合約單。
35. 身為簽核人，我想看到合約單內容（類型、對象、簽約公司、合約編號、起訖日、總金額、備註、掃描檔）與簽核進度，以便做出決定。
36. 身為簽核人，我想下載並檢視 PDF 掃描檔，以便依合約內容判斷。
37. 身為簽核人，我想核准合約單，核准中間關卡時單據仍是簽核中，只有最後一關通過才變成已核准，以便狀態與簽核進度一致。
38. 身為簽核人，我想拒絕合約單並寫下原因，拒絕後單據變成已退回，以便建單人知道為什麼被退回。
39. 身為簽核人，我想未填拒絕原因時被擋下，以便建單人一定看得到理由。
40. 身為簽核人，我想還沒輪到我時無法核准，以便簽核順序不被跳過。
41. 身為簽核人，我想在核准或拒絕失敗時，簽核紀錄與合約單狀態一併回復，以便不會出現「簽核已存檔但單據狀態沒變」。
42. 身為簽核人，我想仍能透過通用簽核進度查詢看到合約單走到哪一關，以便追蹤。
43. 身為簽核人，我想不需要額外權限就能簽核輪到我的合約單，以便簽核由簽核紀錄決定。
44. 身為系統維護者，我想無法透過通用簽核端點對合約單做送簽、核准、拒絕、撤銷、作廢，以便所有動作都經過合約單自己的邏輯。

### 作廢

45. 身為最後一關簽核人，我想作廢已核准的合約單（內容有誤或提前終止），以便單據反映實際情況。
46. 身為最後一關簽核人，我想不論最後一關是指定人員或指定角色，我都能作廢自己核准過的合約單，以便不受簽核設定方式影響。
47. 身為合約建單人，我想作廢後的合約單不能再重送，以便保持歷史單據完整；要再簽就另開新單。
48. 身為使用者，我想只有已核准的合約單可以作廢，其他狀態嘗試作廢時錯誤訊息包含目前狀態，以便知道原因。
49. 身為使用者，我想合約沒有獨立的「終止」狀態，提前終止也以作廢處理，以便狀態單純。

### 列表、搜尋與檢視

50. 身為有檢視權限的人，我想看到全部合約單（不限自己建立的），以便公司層級查詢合約。
51. 身為簽核人，我想在列表也看到待我簽核的合約單，即使我沒有檢視權限，以便能處理。
52. 身為使用者，我想列表欄位為單號、合約編號、類型、合約對象、簽約公司、起訖日、合約總金額、狀態，以便快速瀏覽。
53. 身為使用者，我想已核准的合約單在列表顯示「生效中」或「已到期」標籤，以便一眼看出合約是否仍有效。
54. 身為使用者，我想起日當天與迄日當天都算生效中，迄日隔天才是已到期，以便與合約條款一致。
55. 身為使用者，我想列表可依關鍵字（單號、合約編號）、類型、合約對象、簽約公司、合約單狀態、日期區間（與起訖有交集）與「待我簽核」篩選，以便縮小範圍。
56. 身為使用者，我想依「生效中」或「已到期」篩選已核准的合約單，以便找出目前有效或已過期的合約。
57. 身為使用者，我想列表預設依起日由新到舊並分頁，以便順序穩定且畫面可操作。
58. 身為使用者，我想單據不可編輯時（簽核中、已核准、已作廢）同一頁以唯讀方式檢視，以便不用另外找檢視入口。
59. 身為使用者，我想查詢一張不存在的合約單時得到明確的「找不到資料」訊息，以便不誤認為空結果。

### 權限、紀錄與引用保護

60. 身為管理者，我想有「合約單檢視」權限的人才能進入合約單頁面並檢視，以便控管誰能看合約。
61. 身為管理者，我想有「合約單編輯」權限的人才能建立、編輯、送簽與撤銷，以便控管誰能開單。
62. 身為管理者，我想有「合約單刪除」權限的人才能刪除草稿，以便刪除權限獨立於編輯。
63. 身為管理者，我想不新增任何權限碼，以便沿用既有角色權限設定。
64. 身為管理者，我想合約總金額不受「金額顯示」權限限制，以便有檢視權限的人都看得到。
65. 身為管理者，我想合約單的新增、編輯、刪除、送簽、核准、拒絕、撤銷、作廢都寫入既有操作紀錄，以便事後追查。
66. 身為庫存管理者，我想被合約單引用過的供應商不能刪除、只能停用，以便合約仍顯示原供應商。
67. 身為公司管理者，我想被合約單引用過的公司不能刪除、只能停用，以便合約仍顯示原簽約公司。
68. 身為客戶資料管理者，我想被合約單引用過的客戶不能刪除，以便合約不會指向不存在的客戶；其他單據的引用檢查與客戶停用功能不在本次範圍。

### 上線

69. 身為系統維護者，我想部署時新增合約單資料表且腳本可重複執行，以便誤跑第二次也安全。
70. 身為系統維護者，我想合約單資料表是全新的，不影響既有資料，以便上線沒有資料遷移風險。
71. 身為系統維護者，我想（單號）有唯一索引、供應商、客戶與公司外鍵為限制刪除，以便資料庫層也守住一致。
72. 身為管理者，我想由管理者以現有簽核設定機制建立一組啟用的合約單簽核設定，以便不用改程式就能調整關卡。

## Implementation Decisions

- **新增單據類型與權限**：簽核引擎的單據類型新增「合約單」。沿用既有權限碼合約單檢視（3050）、合約單編輯（30500）、合約單刪除（30501），不新增權限碼。簽核人不需要額外權限，由簽核紀錄決定能否簽核。
- **新增資料表**：合約單資料表（編號 3050），欄位：主鍵、單號（系統產生，唯一索引）、合約編號（必填，長度 64）、合約類型（供應商合約／客戶合約，以列舉儲存）、供應商外鍵（可空）、客戶外鍵（可空）、簽約公司外鍵（必填）、起日、迄日、合約總金額（`decimal(12, 2)`，必填）、備註（選填）、附件路徑（選填，存 SFTP 遠端路徑）、合約單狀態（列舉）、建立與最後修改的時間與人員。供應商、客戶與公司外鍵一律限制刪除（不連帶刪除）。實體模型、DbContext 與資料庫專案同步更新，並依專案慣例在 `docs/sql/` 提供可重複執行的建表腳本（含 `QUOTED_IDENTIFIER` 設定，資料表與索引先判斷是否存在才建立）。
- **類型與對象**：兩個可空外鍵由服務層驗證「依類型恰好填一個」：供應商合約須有供應商且無客戶；客戶合約須有客戶且無供應商。單據只記外鍵，不複製對象名稱（沿用 `docs/inventory/adr/0003`）。
- **合約單狀態**：草稿、簽核中、已核准、已退回、已作廢，以列舉儲存，由合約單自己維護。流轉：草稿 → 簽核中（送簽）；簽核中 → 已核准（最後一關核准）／已退回（拒絕或撤銷）；已退回 → 簽核中（重送）；已核准 → 已作廢；已作廢為終態。中間關卡核准不改狀態；判斷「最後一關核准完成」以引擎回報流程完成為準。「生效中」「已到期」不儲存：已核准且今天介於起訖日（含兩天）為生效中，已核准且今天晚於迄日為已到期；已核准但尚未到起日的合約單不顯示標籤。
- **簽核動作走專屬端點**（依差勤 ADR-0001）：送簽、核准、拒絕、撤銷、作廢五個動作在合約單服務內，以單一資料庫交易包住「引擎動作＋合約單狀態」，任一失敗整筆回滾。前置狀態檢查在引擎動作之前進行（只有草稿或已退回可送簽、只有簽核中可撤銷、只有已核准可作廢），錯誤訊息包含目前狀態。通用簽核控制器對合約單的這五個動作回錯誤（把合約單加入「由模組處理」的類型清單）；簽核進度查詢與「待我簽核」查詢不擋。
- **簽核設定**：不內建關卡，沿用現有簽核設定機制；供應商合約與客戶合約共用同一組。沒有啟用設定或有多組啟用設定時，引擎已回對應錯誤，服務原樣轉出。上線步驟：由管理者或開發者以現有 API 建立一組啟用的合約單簽核設定（目前前端沒有設定畫面）。簽核人作廢權限同出差單：只有最後一關簽核人，且需涵蓋指定人員與指定角色兩種簽核模式（沿用引擎既有的實際簽核人紀錄）。
- **驗證**：欄位驗證用既有的 DataAnnotations 並在服務層以共用方式驗證（比照公司與供應商服務）。儲存草稿即檢查所有必填欄位與長度；合約總金額大於 0 且最多兩位小數；迄日不得早於起日；起訖日可為過去日期；合約編號在非作廢的合約單之間唯一（編輯時排除自己，已作廢單不佔用編號），重複時回明確訊息；不做期間重疊檢查。
- **停用對象規則**：建立、編輯與送簽時，供應商合約的供應商須存在且未停用，簽約公司須存在且未停用；客戶沒有停用概念，只檢查存在。已進入簽核中、已核准的單據不受之後停用影響，列表與檢視仍顯示原對象。
- **附件**：單一 PDF，檔案大小上限 10 MB，經副檔名與內容類型檢查只接受 PDF；沿用現有 SFTP 服務上傳與下載，資料表只存遠端路徑。草稿與已退回可更換（更換時以新路徑覆蓋；舊檔是否清除由實作決定並記錄），簽核中、已核准、已作廢不可更換，已核准不開放補傳。送簽時附件必填，草稿可先不傳。下載走合約單自己的端點並套用檢視權限與「待我簽核」可見範圍。
- **權限與可見範圍**：檢視（3050）可看全部合約單，另加「待我簽核」的單（簽核人不需檢視權限也能在列表看到並簽核，比照出差單）；編輯（30500）可建立、編輯、送簽、撤銷、更換掃描檔；刪除（30501）可刪除草稿；作廢僅最後一關簽核人。合約總金額不受「金額顯示」限制。新增、編輯、刪除與五個簽核動作寫入既有操作紀錄。
- **列表與查詢**：欄位為單號、合約編號、類型、合約對象、簽約公司、起迄日、合約總金額、合約單狀態（含生效中／已到期標籤）。篩選：關鍵字（單號、合約編號）、類型、合約對象、簽約公司、合約單狀態、生效中／已到期、日期區間（與起訖有交集）、待我簽核。預設依起日由新到舊，沿用專案現有分頁與排序寫法。「待我簽核」取自引擎現有的待簽核查詢並限定合約單。列表查詢無法由記憶體資料庫驗證，須在真實資料庫確認。
- **引用保護（修改既有服務）**：供應商刪除與公司刪除的引用檢查把合約單算進去（被合約單引用只能停用，不能刪除）；客戶刪除目前沒有任何引用檢查，本次只新增「被合約單引用不可刪除」一項，不新增客戶停用功能，也不補其他單據的引用檢查。
- **填單用選單**：合約單頁面需要供應商、客戶、公司的選單；供應商與公司選單須排除已停用者，沿用既有選單 API，必要時新增或調整，以不新增權限碼為前提。
- **前端**：新增合約單列表頁（查詢、新增、進入檢視，含「待我簽核」與生效中／已到期篩選），以及建立／編輯／檢視共用的一頁（編輯時有儲存草稿、送簽、撤銷、刪除與 PDF 上傳；簽核中、已核准、已作廢為唯讀；輪到目前使用者簽核時顯示核准與拒絕；已核准且目前使用者為最後一關簽核人時顯示作廢；可下載 PDF）。新增路由與選單入口，簽核進度沿用現有簽核進度查詢。依專案前端規範撰寫。
- **文件**：詞彙表已建立於 `docs/contract/GLOSSARY.md`，實作中若出現新術語就更新。本次判斷不需新增 ADR：簽核單據作法已由 `docs/attendance/adr/0001` 涵蓋；生效中／已到期動態計算與合併成單一資料表都容易回頭調整。

## Testing Decisions

- **好測試的標準**：只驗證對外可觀察的行為（回傳結果、資料庫內容），不驗證內部實作；一個測試對應一個使用者故事或規則。
- **接縫：合約單服務層（唯一新增的接縫）。** 新增合約單服務測試檔，以 SQLite 記憶體庫、假使用者、假序號服務、假簽核引擎與假的 SFTP 服務隔離外部依賴。覆蓋：草稿建立、編輯、刪除；類型與對象恰好一個；必填與長度；合約總金額大於 0 與兩位小數；迄日不得早於起日、過去日期可存；合約編號唯一（含編輯排除自己、作廢單不佔用、跨類型仍唯一）；停用的供應商與簽約公司不可選（建立、編輯、送簽皆檢查）；客戶不設限；送簽的附件必填、無簽核設定、多組設定；核准（中間關卡、最後一關）、拒絕（原因必填）、撤銷、重送、作廢（只有已核准、只有最後一關簽核人）與非法狀態的錯誤訊息；簽核動作失敗時狀態一併回復；列表可見範圍、各項篩選、生效中／已到期計算（含起訖當天邊界）、預設排序與分頁；附件僅限草稿與已退回可更換。
- **延伸既有接縫（不新增檔案）**：延伸供應商服務測試（被合約單引用不可刪除）與公司服務測試（被合約單引用不可刪除）。客戶服務沒有測試檔，「客戶被合約單引用不可刪除」放進合約單服務測試，不為此新增客戶測試檔。
- **前例**：出差單服務測試（簽核單據、假引擎、狀態流轉）、供應商服務測試、公司服務測試與領料服務測試（記憶體資料庫、假使用者、種子資料）。
- **不做**：前端目前沒有自動化測試設定，本次不新增，前端只做建置驗證與手動驗證；簽核引擎本身的行為已由出差單的前置修正涵蓋，不另開真實引擎接縫；SFTP 實際上傳下載不在自動測試範圍。
- **限制**：測試使用 SQLite 記憶體庫，不等於 SQL Server。外鍵限制刪除、唯一索引、部署腳本重複執行、列表查詢，以及 SFTP 真實上傳下載，須由使用者在真實環境驗證。

## Out of Scope

- 合約明細行（料號、數量、單價）、付款條件分期、續約與到期提醒、到期通知。
- 多檔附件、附件版本管理、已核准後補傳附件。
- 依合約類型走不同的簽核流程；簽核設定的管理畫面。
- 合約單匯出、儀表板與跨合約的統計報表。
- 客戶停用功能；客戶被其他單據（出差單、領料單）引用時的刪除保護。
- 期間重疊檢查（同一對象、同一簽約公司）。
- 合約與供應商報價、進貨單、出貨單的連動（例如以合約價驗證單價）。
- 新增權限碼、金額顯示權限控管。
- 獨立的「終止」狀態。

## Further Notes

- 「合約單」是單據，不是主檔；程式與畫面請避免用「合約書、採購合約、銷售合約、簽約對象、合約金額」等詞彙稱呼（見詞彙表 Avoid）。
- 合約編號是紙本合約上的編號，由使用者輸入；單號是系統產生，兩者不同，列表兩者都顯示。
- 外鍵限制刪除與唯一索引在 SQLite 與 SQL Server 的行為可能不同，需使用者在真實資料庫驗證。
- 供應商、公司與客戶的刪除規則因本功能而改變，實作時需同時更新相關測試，並在 ticket 的 Comments 記錄。
- 專案目前沒有簽核設定的管理畫面，上線前需由管理者或開發者以既有 API 建立啟用的合約單簽核設定。
