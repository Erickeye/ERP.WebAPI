# 01: 供應商主檔後端：資料表、供應商服務、權限與部署腳本

**What to build:** 讓有權限的人能透過 API 新增、編輯、停用、啟用、刪除供應商，並取得列表與詳情。沿用現有供應商資料表，補啟用旗標、必填與唯一規則；擴充現有 `_4060SupplierService` 並新增 `_4060SupplierController`；套用既有的供應商檢視、編輯、刪除三個權限與操作紀錄；提供可重複執行的部署腳本。進貨單串接與前端留給 ticket 02、03。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 供應商表新增啟用旗標（預設啟用）；名稱改為必填；付款天數由日期型別改為整數；同步資料庫專案（含 `ERP.DB.sqlproj`）與實體模型
- [x] 供應商編號必填且唯一；統一編號有值時唯一（篩選唯一索引）；唯一索引只在既有資料無衝突時才建立
- [ ] 提供可重複執行的部署腳本（放 `docs/sql/`）：加旗標；空名稱補成「（未命名供應商 {Id}）」後改 NOT NULL；付款天數清空後改整數；列出編號空白或重複、統編重複的資料，不自動修改，無衝突才建索引
- [x] 欄位驗證：必填、長度限制照資料表、統一編號有填時為 8 碼數字；編號或統編與其他供應商重複被擋下並有明確訊息；名稱可重複
- [x] 新增、編輯（含被引用過的供應商，編號與統編仍可改）、停用、啟用、刪除；新增預設為啟用中
- [x] 刪除被進貨單或庫存項目引用過的供應商被擋下並提示改用停用；未被引用可刪除；停用與刪除都不設「最後一間」限制
- [x] 列表：顯示編號、名稱、統編、負責人、聯絡電話、啟用狀態；可依關鍵字（編號、名稱、統編）與啟用狀態篩選；預設啟用中優先再依編號；詳情可取得單筆完整資料（不含信用餘額、最後交易日、暫付金額）
- [ ] 套用權限：供應商檢視（4060）、編輯（40600，含停用與啟用）、刪除（40601）；維護動作寫入操作紀錄，不走簽核
- [x] 新增供應商服務測試檔（SQLite 記憶體庫、假使用者），覆蓋 spec「Testing Decisions」列出的供應商規則；共用種子資料補上供應商編號與名稱
- [x] 更新 `docs/inventory/GLOSSARY.md`（若出現新術語）

## Comments

### 完成記錄（2026-10-21）

實作於 `feat/supplier-management`。後端 `ERP.Tests` 全套 408 項通過（新增 `SupplierServiceTests` 56 項；SQLite 記憶體庫，不等於 SQL Server）。

未勾選項與原因：

- **部署腳本（`docs/sql/供應商資料表.sql`）**：已寫成可重複執行，但沒有在 SQL Server 執行過。加欄位、名稱補佔位值、付款天數改型別、重複資料列出，以及「無衝突才建唯一索引、有衝突只提示」的行為，需使用者在真實資料庫驗證。部署前請先跑腳本第 4 段的查詢，看有沒有重複或空白的供應商編號、重複的統一編號。
- **權限與操作紀錄**：`[PermissionAuthorize]`（供應商檢視 4060、編輯 40600、刪除 40601）與 `[Log]` 已加在 `_4060SupplierController`，只經過編譯（`ERP.Tests` 參照 WebAPI 專案）與靜態檢查，沒有實際呼叫端點驗證；權限項目在角色權限設定勾選即可，不需 SQL。

偏離 ticket／spec 的決定：

- 付款天數範圍限制為 0 到 365 天、信用額度限制為 0 到 9,999,999,999.99（對應 `decimal(12, 2)`）；spec 只說「整數天數」，範圍是實作時補的。
- 供應商編號在資料庫維持可為 NULL（舊資料可能為空），必填由服務層強制：編輯舊的空編號供應商時，必須先補上編號才能存。唯一索引是「有值才唯一」的篩選索引，編號與統編各一個。
- 列表排序：啟用中優先，再依供應商編號（NULL 排最前），最後依 Id；可再用 `SortColumn` 覆寫。
- `GetSupplierSelect`（下拉選單）原樣保留，改成只回傳啟用中並搬到專屬端點屬於 ticket 02。
- 沒有新增詞彙，`docs/inventory/GLOSSARY.md` 已在規劃階段寫入供應商相關術語。
