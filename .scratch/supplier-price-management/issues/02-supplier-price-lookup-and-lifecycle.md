# 02: 填單查詢與供應商生命週期串接

**What to build:** 進貨單建單人填單時，能用供應商與料號查到目前的**供應商報價**作為參考（不自動帶入、不驗證、不阻擋）；供應商被停用時其報價查不到，供應商被刪除時報價一併刪除，不因有報價而擋下刪除。不改進貨單既有的儲存、送簽與簽核流程。

**Blocked by:** 01

**Status:** resolved

- [x] 提供填單查詢：輸入供應商 Id 與料號（完全相符），命中時回品名、單位、單價
- [x] 查無報價、供應商已停用、供應商不存在，都回空結果，不是錯誤
- [ ] 查詢權限為「進貨單編輯」或「庫存編輯」其中之一，不要求供應商檢視；兩者都沒有則無法使用
- [x] 停用供應商時其報價保留；重新啟用後查詢又能命中
- [x] 刪除供應商時連同其全部報價一起刪除，不因存在報價而擋下
- [x] 既有「被進貨單或庫存項目引用的供應商不能刪除」保護不變，仍擋下並提示改用停用
- [x] 延伸供應商服務測試與 `SupplierPriceServiceTests`，覆蓋 spec 列出的填單查詢（命中、料號不完全相符、查無、停用、不存在）與刪除供應商連帶刪報價；同步調整因刪除規則改變而受影響的既有測試
- [x] 進貨單的儲存、送簽與簽核行為不變（既有進貨單測試仍通過）

## Comments

### 完成記錄（2026-10-21）

後端完成，未動前端。`ERP.Tests` 全套 481 項通過（供應商相關 121 項），`dotnet build src/ERP.WebAPI/ERP.WebAPI.csproj` 0 錯誤；服務層紅燈先行、一個切片一個切片實作（SQLite 記憶體庫，不等於 SQL Server）。新增填單查詢測試（命中、前後空白、料號不完全相符、其他供應商、查無、停用、不存在、停用後重新啟用又命中）與刪除供應商連帶刪報價、被進貨單／庫存項目引用仍擋下且報價保留；既有進貨單測試仍通過。

未勾選項與原因：

- **查詢權限**：`GET api/_4061SupplierPrice/Lookup` 加了 `[PermissionAuthorize(進貨單編輯, 庫存編輯)]`（二擇一，不要求供應商檢視），只經過編譯與靜態檢查，沒有實際呼叫端點驗證權限與路由。

偏離 ticket／spec 的決定：

- 空結果的表示方式：回成功，`Data` 為 null（`ResultModel<SupplierPriceLookupVM?>`），已寫在介面註解。料號為空白或 null 也回空結果。料號比對在資料庫端（SQL Server 預設不分大小寫，SQLite 測試分大小寫，不依賴此差異）。
- 刪除供應商：SQLite 測試環境不會連帶刪除（測試驗證過），所以服務層明確刪除報價並與供應商在同一次儲存；不依賴資料庫外鍵。
