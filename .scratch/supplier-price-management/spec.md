# 供應商價格管理（供應商報價維護與填單查詢）

Status: ready-for-agent

相關文件：`GLOSSARY-MAP.md`（庫存管理 context，術語以 `docs/inventory/GLOSSARY.md` 為準：供應商報價、供應商、停用（供應商））、`docs/inventory/adr/0002`（庫存以供應商＋庫位＋料號為單位，不建品項主檔，報價沿用此前提）、`docs/inventory/adr/0003`（單據只記供應商外鍵）。範本參考 `.scratch/supplier-management/spec.md`（供應商主檔，權限、操作紀錄、前端與部署腳本慣例相同）。

## Problem Statement

供應商主檔已可維護，但沒有地方記錄「某供應商對某料號議定的單價」。填進貨單時，建單人只能憑記憶或另外的表格輸入單價，容易填錯，也無從對照。系統目前唯一的價格資料是進貨單明細上的實際成交價，既不是事先議定的參考價，也無法在填單前查到。

## Solution

提供**供應商價格管理**：有權限的人可以針對每一間供應商維護其**供應商報價**（料號、品名、單位、單價、備註），並在該供應商之下檢視與搜尋。同一供應商的同一料號只有一筆報價，只存現價，改價直接覆蓋。

填進貨單時，可以用供應商與料號查詢目前的供應商報價，作為填單參考。查詢只是參考：不自動帶入單價，也不阻擋與報價不同的進貨單，進貨單既有的驗證與簽核流程都不變。

供應商報價不是進貨單上的實際成交價，也不影響庫存與付款；本次不做比價報表、歷史價格與多幣別。

## User Stories

### 供應商報價維護

1. 身為庫存管理者，我想在某間供應商之下新增一筆供應商報價，以便記錄該供應商某料號議定的單價。
2. 身為庫存管理者，我想填寫料號、品名、單位與單價，以便報價資料完整可辨識。
3. 身為庫存管理者，我想選填備註，以便記錄報價的補充說明（例如議價條件）。
4. 身為庫存管理者，我想未填必填欄位或超過欄位長度（料號 64、品名 128、單位 16）時被擋下並看到明確訊息，以便資料符合資料表的限制。
5. 身為庫存管理者，我想單價必須大於 0 且最多兩位小數，不合規定時被擋下，以便不會存入零、負數或超出精度的單價。
6. 身為庫存管理者，我想同一供應商的料號不可重複，重複時被擋下並看到明確訊息，以便一個料號在一間供應商只有一個報價。
7. 身為庫存管理者，我想不同供應商可以有相同的料號，以便各供應商各自維護自己的報價。
8. 身為庫存管理者，我想同一供應商之下品名可以重複，以便同品名但不同料號的品項並存。
9. 身為庫存管理者，我想編輯既有的供應商報價（料號、品名、單位、單價、備註），以便更正或調整價格。
10. 身為庫存管理者，我想編輯時修改料號，但不能與同供應商的其他報價重複，以便更正打錯的料號。
11. 身為庫存管理者，我想改價時直接覆蓋原單價，不保留歷史價格，以便報價永遠是現行的一個值。
12. 身為庫存管理者，我想刪除一筆供應商報價，以便清掉不再適用或誤建的資料。
13. 身為庫存管理者，我想刪除供應商報價時不受任何引用限制，以便不用處理與進貨單的關聯（進貨單不引用報價）。
14. 身為庫存管理者，我想已停用的供應商仍可維護其報價，以便停用期間也能整理資料。
15. 身為庫存管理者，我想查詢一間不存在的供應商的報價時得到明確的「找不到供應商」訊息，以便不會把空結果誤認為沒有報價。

### 列表與搜尋

16. 身為庫存管理者，我想在某供應商之下看到報價列表，欄位為料號、品名、單位、單價、備註與最後修改時間，以便快速瀏覽。
17. 身為庫存管理者，我想列表可用關鍵字比對料號與品名篩選，以便在報價很多時縮小範圍。
18. 身為庫存管理者，我想列表預設依料號排序，以便順序穩定可預期。
19. 身為庫存管理者，我想列表分頁，以便報價很多時畫面仍可操作。
20. 身為庫存管理者，我想檢視單一報價的完整資料，以便確認備註與建立、修改資訊。
21. 身為庫存管理者，我想從供應商列表直接進入該供應商的報價管理頁，以便不用另外找入口。

### 權限與紀錄

22. 身為管理者，我想有「供應商檢視」權限的人才能進入報價管理頁並看到報價列表與詳情，以便控管誰能看報價。
23. 身為管理者，我想有「供應商編輯」權限的人才能新增與編輯報價，以便控管誰能改價。
24. 身為管理者，我想有「供應商刪除」權限的人才能刪除報價，以便刪除權限獨立於編輯。
25. 身為管理者，我想報價的新增、編輯、刪除都寫入操作紀錄，以便事後追查誰在何時改過價格。
26. 身為管理者，我想報價的維護不需要簽核，以便有權限的人可以直接操作。
27. 身為管理者，我想不新增任何權限碼，以便沿用既有的角色權限設定。

### 填進貨單時查詢報價

28. 身為進貨單建單人，我想用供應商與料號查詢目前的供應商報價，以便填單時參考議定單價。
29. 身為進貨單建單人，我想查詢結果包含品名、單位與單價，以便對照明細上的欄位。
30. 身為進貨單建單人，我想料號必須完全相符才命中，以便不會因模糊比對查到別的品項。
31. 身為進貨單建單人，我想查無報價時得到空結果而不是錯誤，以便畫面可以正常顯示「無報價」。
32. 身為進貨單建單人，我想供應商已停用或不存在時也只得到空結果，以便停用供應商不會洩出報價。
33. 身為進貨單建單人，我想只要有「進貨單編輯」或「庫存編輯」權限其中之一就能查詢，而不需要供應商檢視權限，以便我能填單。
34. 身為管理者，我想沒有「進貨單編輯」也沒有「庫存編輯」權限的人無法使用這個查詢，以便報價不外流給與填單無關的人。
35. 身為進貨單建單人，我想實際單價與報價不同時仍可儲存與送簽，以便報價只是參考而不是限制。
36. 身為進貨單建單人，我想查詢不會自動覆蓋我已填的單價，以便由我決定要不要採用。

### 供應商生命週期

37. 身為庫存管理者，我想停用供應商時它的報價保留不刪除，以便重新啟用後報價仍在。
38. 身為庫存管理者，我想停用供應商的報價不會被填單查詢回傳，以便新進貨單不會參考到停用供應商的價格。
39. 身為庫存管理者，我想刪除供應商時連同其全部報價一起刪除，以便報價不會因為供應商刪除而殘留，也不會因為有報價而擋下刪除。
40. 身為庫存管理者，我想供應商仍受既有「被進貨單或庫存項目引用就不能刪除」的規則保護，以便報價連帶刪除不會改變這項保護。

### 上線

41. 身為系統維護者，我想部署時新增報價資料表且腳本可重複執行，以便誤跑第二次也安全。
42. 身為系統維護者，我想報價資料表是全新的，不影響既有資料，以便上線沒有資料遷移風險。
43. 身為系統維護者，我想（供應商 Id＋料號）有唯一索引、供應商外鍵為連帶刪除，以便資料庫層也守住唯一與一致。

## Implementation Decisions

- **新增資料表**：新增供應商報價資料表（接在供應商資料表之後，編號 4061），欄位：主鍵、供應商外鍵、料號（64，必填）、品名（128，必填）、單位（16，必填）、單價（`decimal(12, 2)`，必填）、備註（選填）、建立時間與建立人員、最後修改時間與修改人員。（供應商 Id、料號）建唯一索引；供應商外鍵採連帶刪除。實體模型、DbContext 與資料庫專案同步更新，並依專案慣例在 `docs/sql/` 提供可重複執行的建表腳本（資料表與索引都先判斷是否存在才建立，沒有既有資料問題；腳本需包含 `QUOTED_IDENTIFIER` 設定，與供應商部署腳本一致）。
- **服務與端點**：新增供應商報價服務與控制器，不併入既有供應商服務，以免該服務過大。功能為：以供應商 Id 取得列表（關鍵字、分頁、排序）、取得單筆、新增、編輯、刪除、填單查詢。列表、排序與分頁使用既有慣例；回傳訊息使用既有的結果模型與錯誤碼慣例。
- **欄位與驗證**：欄位驗證用既有的 DataAnnotations，並在服務層以共用方式驗證（比照公司與供應商服務）。單價必填、大於 0，最多兩位小數；料號、品名、單位必填，長度與進貨單明細欄位一致。（供應商＋料號）唯一檢查在服務層做，編輯時排除自己；重複時回明確訊息。品名不做唯一。
- **料號比對**：料號比對沿用資料庫排序規則（不另做大小寫轉換或去空白的特殊處理）；儲存前不修剪以外的正規化，與進貨單明細的料號保持同樣的原樣文字。
- **供應商相依規則**：新增、編輯、刪除報價時，供應商必須存在，否則回「找不到供應商」；供應商已停用不影響維護。填單查詢只命中**啟用中**供應商的報價；供應商停用或不存在都回空結果。
- **填單查詢契約**：輸入供應商 Id 與料號（完全相符）；命中時回品名、單位、單價；查無回空結果，不回錯誤。不修改進貨單的任何儲存、送簽或簽核流程。
- **刪除供應商的連帶處理**：修改既有供應商刪除邏輯，使其不因存在報價而擋下，並連同報價一起刪除（先前的引用保護只看進貨單與庫存項目，不變）。連帶刪除依資料庫外鍵完成；服務層刪除前的引用檢查不應把報價算進去。
- **權限與紀錄**：沿用供應商檢視（4060）、供應商編輯（40600，含新增與編輯報價）、供應商刪除（40601，含刪除報價）；填單查詢要求「進貨單編輯」或「庫存編輯」其中之一，比照填單用供應商選單，不要求供應商檢視。報價的新增、編輯、刪除寫入既有操作紀錄；不走簽核。不新增權限碼。
- **前端**：在供應商列表頁每列新增「報價」入口，進入獨立的報價管理頁（路由帶供應商 Id）；頁內為該供應商的報價列表（欄位、關鍵字篩選、預設依料號排序、分頁）與新增、編輯（對話框）、刪除（依權限顯示按鈕）。新增路由並依權限顯示入口，比照現有供應商頁面與 API 封裝撰寫，遵守專案前端規範。進貨單與庫存頁面專案目前沒有，填單查詢的前端串接延後，只提供後端 API。
- **文件**：詞彙表已新增「供應商報價」；實作中若出現新術語，更新 `docs/inventory/GLOSSARY.md`。本次判斷不需新增 ADR（只存現價是加法，日後要改成有歷史並不難回頭）。

## Testing Decisions

- **好測試的標準**：只驗證對外可觀察的行為（回傳結果、資料庫內容），不驗證內部實作；一個測試對應一個使用者故事或規則。
- **接縫：服務層。** 新增供應商報價服務測試檔，覆蓋：新增、編輯、必填與長度驗證、單價大於 0 與兩位小數、（供應商＋料號）唯一（含編輯改料號與排除自己）、不同供應商可同料號、品名可重複、刪除、供應商不存在、停用供應商仍可維護、列表關鍵字（料號與品名）與預設排序與分頁、填單查詢（命中、料號不完全相符、查無回空、停用供應商回空、不存在供應商回空）。刪除供應商連帶刪除報價的行為，延伸既有供應商服務測試檔，另覆蓋「有報價的供應商可刪除且報價一併消失」「仍被進貨單引用者不可刪」。
- **前例**：供應商服務測試、公司服務測試與領料服務測試（記憶體資料庫、假使用者、種子資料）。
- **不做**：前端目前沒有自動化測試設定，本次不新增，前端只做建置驗證與手動驗證。
- **限制**：測試使用 SQLite 記憶體庫，不等於 SQL Server。外鍵連帶刪除、唯一索引、部署腳本的重複執行，以及列表查詢，須由使用者在真實資料庫驗證。

## Out of Scope

- 進貨單前端頁面與填單查詢的前端串接（專案目前沒有進貨單頁面）。
- 生效期間、失效日與價格歷史；比價報表與跨供應商的報價總覽。
- 幣別、含稅或未稅旗標；數量階梯價、最小訂購量與交期。
- 報價的停用旗標與簽核；報價匯入與匯出。
- 品項主檔與以品項為單位的多供應商比價（ADR-0002 已決定先不做）。
- 進貨單依報價自動帶入單價、或以報價驗證單價。
- 新增權限碼。

## Further Notes

- 「供應商報價」是我方維護的參考單價，不是進貨單上實際成交的單價；程式與畫面請避免用「進價、成本價、採購價、價目」稱呼。
- 進貨單明細的料號、品名、單位都是自由文字，報價以文字料號完全相符來對應；若兩邊料號寫法不一致（多空白、大小寫由資料庫排序規則決定），就查不到，這是沒有品項主檔下的已知限制。
- 刪除供應商的規則因本功能而改變（報價不擋下並連帶刪除），實作時需同時更新供應商相關測試，並在 Comments 記錄。
- 外鍵連帶刪除與唯一索引在 SQLite 與 SQL Server 的行為可能不同，需使用者在真實資料庫驗證。
