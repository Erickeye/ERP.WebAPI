# 公司管理（多公司主檔與單據公司）

Status: resolved

> 三張 ticket 皆為 resolved；領料單前端因專案尚無領料單頁面而延後（後端 API 已就緒）。SQL 腳本與前端畫面仍待使用者在真實環境驗證，細節見各 ticket 的 Comments。

相關文件：`GLOSSARY-MAP.md`（公司管理 context，術語以 `docs/company/GLOSSARY.md` 為準；單據相關術語見庫存管理與差勤的詞彙表）、`docs/company/adr/0001`（單據只記公司外鍵，不存名稱快照）、`docs/inventory/adr/0001` 與 `docs/attendance/adr/0001`（領料單、出差單的狀態與簽核動作由單據自己維護，本規格不改動這些流程）。

## Problem Statement

一個企業通常旗下不只一間公司，但系統目前沒有「這張單據屬於哪間公司」的概念。領料單與出差單填單時無法指定公司，事後也無法依公司查詢或篩選。資料庫雖已有一張公司資料表（`t_1080Company`），但沒有任何功能使用它：沒有管理畫面，單據也沒有引用它，目前資料表是空的。

## Solution

提供**公司管理**：有權限的人可以新增、編輯、停用與啟用、刪除**公司**，並在列表檢視。領料單與出差單新增**單據公司**欄位：建單時必填，從啟用中的公司挑選，送簽後鎖定；列表可依公司篩選，並顯示公司簡稱。

公司被單據引用過就不能刪除，只能**停用**；停用後不再出現在填單選項，但歷史單據仍顯示原公司。單據只記公司外鍵，公司改名視為更正，歷史單據跟著顯示新資料（ADR-0001）。

本次只做公司主檔與兩種單據的歸屬，不切分單號、簽核流程、庫位、員工歸屬。

## User Stories

### 公司主檔維護

1. 身為公司管理者，我想新增一間公司，以便讓單據可以選到它。
2. 身為公司管理者，我想填寫公司簡稱、公司全名、統一編號、稅籍編號、負責人與登記地址，以便記錄法人實體的必要資料。
3. 身為公司管理者，我想選填電話、傳真、送貨地址、發票地址、銀行名稱、支票帳號、匯款帳號、付款天數、成立日期與發票格式，以便把非必要資料也留存。
4. 身為公司管理者，我想統一編號只接受 8 碼數字，以便不會存入格式錯誤的統編。
5. 身為公司管理者，我想新增或編輯時，若統一編號與其他公司重複就被擋下並看到明確訊息，以便一個法人實體不會有兩筆資料。
6. 身為公司管理者，我想新增或編輯時，若公司簡稱與其他公司重複就被擋下並看到明確訊息，以便填單時分得出是哪一間。
7. 身為公司管理者，我想未填必填欄位或超過欄位長度時被擋下，以便資料符合資料表的限制。
8. 身為公司管理者，我想編輯既有公司的資料，包含已被單據引用的公司，以便更正錯字或統編。
9. 身為公司管理者，我想在公司被單據引用後仍可修改簡稱與統編，以便改名視為更正而不是換公司。
10. 身為公司管理者，我想新增的公司預設為啟用中，以便立刻可以被選用。
11. 身為公司管理者，我想停用一間公司，以便讓它不再出現在填單選項。
12. 身為公司管理者，我想重新啟用一間已停用的公司，以便恢復它的使用。
13. 身為公司管理者，我想在只剩一間啟用中公司時，停用它被擋下並看到明確訊息，以便不會讓所有人都填不了單。
14. 身為公司管理者，我想刪除一間從未被任何單據引用過的公司，以便清掉誤建的資料。
15. 身為公司管理者，我想刪除被單據引用過的公司時被擋下，並提示改用停用，以便歷史單據不會失去公司。
16. 身為公司管理者，我想在刪除最後一間啟用中公司時被擋下，以便與停用的限制一致。
17. 身為公司管理者，我想在列表看到公司簡稱、公司全名、統一編號、負責人與啟用狀態，並可依狀態與關鍵字篩選，以便快速找到公司。
18. 身為公司管理者，我想列表預設把啟用中的公司排在前面，以便常用的公司先看到。
19. 身為管理者，我想公司的新增、編輯、停用、啟用、刪除都寫入操作紀錄，以便事後追查。
20. 身為管理者，我想公司的維護不需要簽核，以便有權限的人可以直接操作。

### 權限

21. 身為管理者，我想有「公司檢視」權限的人才能進入公司管理頁並看到列表與詳情，以便控管誰能看公司資料。
22. 身為管理者，我想有「公司編輯」權限的人才能新增、編輯、停用與啟用公司，以便控管誰能改主檔。
23. 身為管理者，我想有「公司刪除」權限的人才能刪除公司，以便刪除的權限獨立於編輯。
24. 身為一般填單人，我想不需要公司檢視權限，就能在領料單與出差單的下拉選單看到啟用中的公司，以便我能填單。
25. 身為管理者，我想沒有「領料單編輯」或「出差單」權限的人無法取得填單用的公司選單，以便公司資料不外流給與填單無關的人。

### 領料單的單據公司

26. 身為領料單建單人，我想在建立領料單時選擇單據公司，以便領料歸屬到正確的公司。
27. 身為領料單建單人，我想單據公司必填，未選就被擋下，以便每張領料單都有歸屬。
28. 身為領料單建單人，我想下拉選單只列出啟用中的公司，以便不會選到已停用的公司。
29. 身為領料單建單人，我想在只有一間啟用中公司時，新增領料單自動帶入該公司，以便少選一個欄位。
30. 身為領料單建單人，我想在草稿與已退回狀態修改單據公司，以便選錯時可以更正。
31. 身為領料單建單人，我想送簽後單據公司無法修改，以便簽核內容不會在送簽後被更動。
32. 身為領料單建單人，我想編輯草稿時，若原本的公司已被停用，仍看得到它並標示「已停用」，以便知道原值是什麼。
33. 身為領料單建單人，我想送簽時若所選公司已停用就被擋下並提示改選，以便停用的公司不會被新單據使用。
34. 身為領料單建單人，我想已送簽或已核准的領料單即使公司後來被停用，簽核與核准仍照常進行，以便停用不影響進行中的單據。
35. 身為領料單使用者，我想在領料單列表與詳情看到公司簡稱，詳情另外顯示統一編號，以便知道單據歸屬。
36. 身為領料單使用者，我想在領料單列表依公司篩選，以便只看某間公司的領料。
37. 身為領料單建單人，我想庫位不受公司限制，以便任何公司都能搭配任何庫位（庫位目前沒有公司歸屬）。

### 出差單的單據公司

38. 身為出差單建單人，我想在建立出差單時選擇單據公司，以便出差歸屬到正確的公司。
39. 身為出差單建單人，我想單據公司必填，未選就被擋下，以便每張出差單都有歸屬。
40. 身為出差單建單人，我想下拉選單只列出啟用中的公司，且只有一間時自動帶入，以便填單更快。
41. 身為出差單建單人，我想在草稿與已退回狀態修改單據公司，簽核中、已核准、已作廢時不可修改，以便與其他欄位的鎖定規則一致。
42. 身為出差單建單人，我想編輯草稿時，若原本的公司已被停用，仍看得到它並標示「已停用」，送簽時被擋下並提示改選，以便停用的公司不會被新單據使用。
43. 身為出差單使用者，我想在出差單列表與詳情看到公司簡稱，並可在列表依公司篩選，以便依公司彙整出差。
44. 身為簽核人，我想核准、拒絕、撤銷、作廢出差單與領料單的流程不因公司而改變，以便既有簽核照常運作。

### 既有資料與上線

45. 身為系統維護者，我想部署時系統自動建立一間預設公司並把既有領料單與出差單回填到它，以便上線後舊單據仍然完整。
46. 身為系統維護者，我想預設公司的占位資料（統編、稅籍編號、負責人、地址）清楚標示「待更正」，以便上線後能在公司管理頁更正。
47. 身為系統維護者，我想部署腳本可重複執行而不產生重複的預設公司或重複欄位，以便誤跑第二次也安全。

## Implementation Decisions

- **沿用現有公司資料表**：不另建新表。現有欄位保留，新增啟用旗標（預設啟用）。公司簡稱與統一編號各建唯一索引，必填規則與長度限制照現有資料表（統編 8 碼數字、稅籍編號 9 碼）。資料表目前沒有資料，加唯一索引不會與既有資料衝突。實體模型與資料庫專案同步更新，並依專案慣例提供既有資料庫的 SQL 腳本。
- **單據公司欄位**：領料單與出差單的單頭各新增公司外鍵，指向公司主檔，並加索引。依 ADR-0001 只存 Id，不存名稱快照。
- **部署腳本順序**（放在既有的 SQL 腳本資料夾，可重複執行）：(1) 公司表加啟用旗標與唯一索引；(2) 若沒有任何公司，新增一間預設公司：簡稱「預設公司」、全名「預設公司（待更正）」、統一編號 `00000000`、稅籍編號 `000000000`、負責人「待更正」、登記地址「待更正」，腳本註解標明這些是占位值需更正；(3) 兩張單據表加公司欄位（先允許空值）；(4) 用預設公司回填；(5) 改為必填並加外鍵。
- **公司服務與端點**：新增公司服務（列表、取得單筆、新增、編輯、停用、啟用、刪除）與對應控制器，以及一個給填單用的「啟用中公司選單」查詢。選單查詢可指定一個公司 Id，使該公司即使已停用也一併回傳並標示已停用，供編輯草稿顯示原值。
- **權限**：新增三個功能權限項目：公司檢視（1080）、公司編輯（10800，含停用與啟用）、公司刪除（10801），依現有權限機制設定。填單用的公司選單端點只要求使用者具有「領料單編輯」或「出差單」其中之一，不要求公司檢視。
- **停用與刪除規則**：停用或刪除一間啟用中公司時，若它是最後一間啟用中公司就擋下。刪除時若任一領料單或出差單引用它就擋下，並提示改用停用。停用、啟用、刪除、新增、編輯寫入現有的操作紀錄機制；公司維護不走簽核。
- **單據規則**：領料單與出差單的新增與編輯都要求公司必填，且公司必須存在。只有草稿與已退回狀態可改單據公司（沿用兩種單據現有「簽核中、已核准、已作廢不可編輯」的規則，不新增狀態判斷）。送簽時檢查單據公司是否啟用中，已停用就擋下並提示改選；已送簽、已核准、已作廢的單據不受之後的停用影響。送簽前的其他檢查與簽核引擎流程不變。
- **列表與詳情**：領料單與出差單的列表資料與詳情加上公司簡稱，詳情另含統一編號。兩個列表新增「公司」篩選條件（單選，與其他條件並用）。現有的可見範圍、排序與分頁不變。
- **前端**：新增公司管理列表頁與編輯頁（新增、編輯、停用與啟用、刪除、篩選），新增路由與選單入口，依權限顯示。領料單與出差單的編輯頁新增公司下拉：只有一間啟用中公司且為新單時自動帶入；編輯時若原公司已停用，以「（已停用）」標示並在送簽時由後端擋下。兩個列表頁加公司欄位與篩選。依專案前端規範撰寫。
- **匯出**：公司篩選與簡稱欄位只做在畫面列表；若領料單或出差單現有匯出功能，匯出多一欄公司簡稱。（出差單本次規格明確沒有匯出；領料單是否有匯出，實作時確認。）
- **文件**：公司管理的詞彙表與 ADR 已建立（見相關文件）；實作中若出現新術語，更新 `docs/company/GLOSSARY.md`。

## Testing Decisions

- **好測試的標準**：只驗證對外可觀察的行為（回傳結果、資料庫內容、單據狀態），不驗證內部實作；一個測試對應一個使用者故事或規則。
- **接縫：服務層，三個既有或新增的服務各一個測試檔。**
  - 新增公司服務測試：覆蓋新增、編輯、欄位驗證、統編與簡稱唯一、停用與啟用、最後一間啟用中公司的保護、刪除與被引用的保護、填單用選單（含指定已停用公司一併回傳）、列表篩選。
  - 延伸領料服務測試與出差單服務測試：覆蓋單據公司必填、僅啟用中公司可選、草稿與已退回可改而其他狀態不可改、送簽時公司已停用被擋下、已送簽單據不受停用影響、列表依公司篩選與回傳公司簡稱。
- **既有測試與種子資料要跟著改**：兩張單據的公司欄位改為必填後，共用種子資料必須先建立一間公司，既有測試才能建單；這屬於種子資料的調整，不是新接縫。
- **前例**：領料單服務測試與出差單服務測試（記憶體資料庫、假簽核引擎、假使用者、假流水號、種子資料）。
- **不做**：前端目前沒有自動化測試設定，本次不新增，前端靠手動驗證。
- **限制**：測試使用 SQLite 記憶體庫，不等於 SQL Server。唯一索引、外鍵、部署腳本的回填與重複執行、以及列表查詢，須由使用者在真實資料庫驗證。

## Out of Scope

- 進貨單與請假單、公文、零用金等其他單據的公司欄位，另案；進貨單還在舊簽核流程，需一併處理 `Payer`、`Authorizator` 等欄位。
- 依公司切分單號、簽核流程、庫位、員工與使用者的公司歸屬、依使用者限制可選公司。
- 公司主檔的簽核。
- 單據上的公司名稱快照（ADR-0001 已決定不做）。
- 客戶與供應商與公司之間的關聯。
- 以公司為單位的報表或統計。
- 前端自動化測試。

## Further Notes

- 「公司」指我方旗下的法人實體，不是客戶或供應商；程式與畫面請避免用「集團、分公司、客戶」稱呼。
- 規格中補上的一個假設：刪除最後一間啟用中公司，與停用適用同一個保護。對話中只明確討論過停用，這是依一致性做的延伸，若不同意請在實作前提出。
- 預設公司是占位資料，上線後應立即到公司管理頁改成真實的名稱與統編；統編改過之後，歷史單據顯示新值是預期行為。
- 專案根目錄的 `dbData/ERP.bak` 在目前工作樹顯示為已刪除，與本規格無關。
