# 01: 公司主檔：資料表、公司服務、權限與公司管理頁

**What to build:** 讓有權限的人能在畫面上新增、編輯、停用、啟用、刪除公司，並在列表檢視。從資料表、服務、API 到前端頁面一次打通。沿用現有的公司資料表，補啟用旗標與唯一索引；新增公司服務與控制器、填單用的「啟用中公司選單」查詢（供後續兩張 ticket 使用）、三個功能權限，以及公司管理的列表頁與編輯頁。部署腳本前半（加欄位、索引、預設公司）也在此 ticket。單據的公司欄位留給 ticket 02、03。

**Blocked by:** None (can start immediately)

## Comments

### 完成記錄（2026-10-20）

實作於 `feat/company-management`（commit `71aa352`）。後端 `ERP.Tests` 全套 321 項通過（基準 276 項 + 新增 `CompanyServiceTests` 45 項；SQLite 記憶體庫，不等於 SQL Server）；前端用 `agent-vue-build.sh` 驗證能建置（vite build 通過，未在瀏覽器實際操作）。

未勾選項與原因：

- **既有資料庫腳本（`docs/sql/公司資料表.sql`）**：已寫成可重複執行，但沒有在 SQL Server 執行過，加欄位、唯一索引、預設公司的重複執行行為需使用者在真實資料庫驗證。
- **停用或刪除最後一間啟用中公司被擋、被引用過不可刪**：「最後一間」的保護已有測試；「被領料單或出差單引用」目前只有占位實作（永遠回傳未引用），因為兩張單據表還沒有公司欄位，要等 ticket 02、03 加欄位時在公司服務的 `IsReferencedAsync` 補上查詢與測試。
- **權限（1080／10800／10801）與操作紀錄**：權限列舉與 `[PermissionAuthorize]`、`[Log]` 已加在控制器，只經過編譯與靜態檢查，沒有實際呼叫端點驗證；權限項目依既有機制，在角色權限設定勾選即可，不需 SQL。
- **填單用「啟用中公司選單」**：服務層有測試（只列啟用中、includeId 帶出已停用公司、不重複、未知 Id 略過）；「領料單編輯或出差單其中之一」的授權屬控制器層，同上未實測。
- **前端**：只驗證能建置；前端沒有權限模型，按鈕不依權限隱藏，沒有權限時由後端回「權限不足」、頁面顯示該訊息。

偏離 ticket／spec 的決定：

- 公司簡稱與統編的唯一檢查、欄位驗證都在 Service 內做（欄位規則沿用 `CompanyAddVM` 的 DataAnnotations，以 `Validator` 重用），以便在服務層接縫測試；Controller 另有 `[ValidateModel]`。
- 填單選單依建立順序（Id）排序，沒有依簡稱排序，因為中文簡稱的排序在 SQLite 與 SQL Server 的定序下結果不同。
- 新增公司成功後回到列表頁（不是停在編輯頁）。
- 本 ticket 沒有新增詞彙，`docs/company/GLOSSARY.md` 無變動。
