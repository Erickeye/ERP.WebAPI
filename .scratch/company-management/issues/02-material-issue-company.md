# 02: 領料單加單據公司

**What to build:** 讓領料單在建單時選擇單據公司（必填），並能在列表依公司篩選、顯示公司簡稱。從資料表回填、服務規則、API 到前端頁面一次打通：領料單新增公司外鍵（依 ADR-0001 只存 Id）、部署腳本後半（加欄位、用預設公司回填舊單據、改必填與外鍵）、建單與編輯的必填與鎖定規則、送簽時擋停用公司、列表與詳情顯示、編輯頁下拉。庫位不受公司限制，簽核流程不變。

**Blocked by:** 01

**Status:** resolved

- [ ] 領料單表新增公司欄位與索引；既有資料庫腳本先允許空值、用預設公司回填、再改必填並加外鍵，可重複執行；同步資料庫專案與實體模型
- [x] 新增與編輯領料單要求單據公司必填且公司必須存在；只有草稿與已退回可改單據公司（沿用現有「簽核中、已核准、已作廢不可編輯」規則，不新增狀態判斷）
- [x] 送簽時所選公司已停用就被擋下並提示改選；已送簽、已核准、已作廢的單據不受之後的停用影響；其他送簽檢查與簽核引擎流程不變
- [x] 列表與詳情回傳公司簡稱，詳情另含統一編號；列表新增「公司」篩選，與現有條件並用，可見範圍、排序、分頁不變
- [x] 公司服務的「被引用過」判斷納入領料單，被領料單引用的公司不可刪除
- [ ] 前端：編輯頁新增公司下拉（只列啟用中；新單且只有一間時自動帶入；編輯草稿時原公司已停用則顯示「（已停用）」）、列表加公司欄位與篩選、詳情顯示簡稱與統編
- [ ] 現有領料單匯出若存在，多一欄公司簡稱（實作時確認有無匯出；若沒有，在 Comments 記錄）
- [x] 調整共用種子資料，先建立一間公司，使既有測試仍可建單
- [x] 延伸領料服務測試：公司必填、僅啟用中公司可選、草稿與已退回可改而其他狀態不可改、送簽時公司已停用被擋下、已送簽單據不受停用影響、列表依公司篩選與回傳簡稱

未勾選項與原因：

- **既有資料庫腳本（`docs/sql/領料單公司欄位.sql`）**：已寫成可重複執行（加欄位允許空值 → 用「預設公司」回填 → 改必填 → 加索引與外鍵），但沒有在 SQL Server 執行過；需使用者在真實資料庫驗證，並確認先執行過 `公司資料表.sql`。
- **前端（編輯頁公司下拉、列表欄位與篩選、詳情顯示）**：目前前端專案**沒有任何領料單頁面**（`src/ERP.Vue` 沒有領料單的 view、api、路由），所以沒有可加的畫面；後端 API 已就緒（`MaterialIssueAddVM.CompanyId`、列表與詳情的公司簡稱、統編、啟用狀態，搜尋條件 `CompanyId`，填單用選單沿用 ticket 01 的公司選單 API）。待領料單前端頁面建立時，再依本 ticket 的前端條件實作；此項改記為延後，不算本 ticket 完成。
- **匯出**：領料單有匯出（PDF／Xlsx 共用 `Export`），已多一欄「公司」（公司簡稱）；匯出依賴 Xlsx 模板檔，測試專案沒有該模板，所以沒有自動化測試，只經過編譯，需使用者在真實環境匯出確認。

偏離 ticket／spec 的決定：

- 編輯時「維持原本已停用的公司」允許儲存其他欄位，「改選一間已停用的公司」被擋，與 spec 使用者故事 32、33 一致；送簽時才擋停用公司。
- 錯誤碼使用既有的 `FieldValueIsInvalid`，訊息「所選公司已停用，請改選其他公司」。
- 詳情與列表額外回傳 `CompanyIsActive`，讓前端能標示「（已停用）」。
- 列表與詳情的查詢會 join 建單人，種子資料沒有使用者時查不到資料；查詢測試因此先建立一筆使用者（Id 7），寫入類測試不受影響。
