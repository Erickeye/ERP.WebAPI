# 03: 出差單加單據公司

**What to build:** 讓出差單在建單時選擇單據公司（必填），並能在列表依公司篩選、顯示公司簡稱。做法與 ticket 02 相同，套用在出差單：新增公司外鍵（依 ADR-0001 只存 Id）、部署腳本後半、建單與編輯的必填與鎖定規則、送簽時擋停用公司、列表與詳情顯示、編輯頁下拉。重疊檢查與簽核流程不變。

**Blocked by:** 01

**Status:** resolved

- [ ] 出差單表新增公司欄位與索引；既有資料庫腳本先允許空值、用預設公司回填、再改必填並加外鍵，可重複執行；同步資料庫專案與實體模型（與 ticket 02 的腳本放在不同檔案，各自可獨立部署）
- [x] 新增與編輯出差單要求單據公司必填且公司必須存在；只有草稿與已退回可改單據公司（沿用現有狀態規則）
- [x] 送簽時所選公司已停用就被擋下並提示改選；已送簽、已核准、已作廢的單據不受之後的停用影響；重疊檢查與簽核引擎流程不變
- [x] 列表與詳情回傳公司簡稱，詳情另含統一編號；列表新增「公司」篩選，與現有條件並用，可見範圍、排序、分頁不變
- [x] 公司服務的「被引用過」判斷納入出差單，被出差單引用的公司不可刪除
- [ ] 前端：編輯頁新增公司下拉（規則同 ticket 02）、列表加公司欄位與篩選、詳情顯示簡稱與統編
- [x] 調整共用種子資料以建立公司（若 ticket 02 已先調整則沿用），使既有出差單測試仍可建單
- [x] 延伸出差單服務測試：公司必填、僅啟用中公司可選、草稿與已退回可改而其他狀態不可改、送簽時公司已停用被擋下、已送簽單據不受停用影響、列表依公司篩選與回傳簡稱

## Comments

### 完成記錄（2026-10-20）

實作於 `feat/company-management`（commit `8812589`）。全套 `ERP.Tests` 351 項通過（ticket 02 後為 336 項，本 ticket 新增 15 項；SQLite 記憶體庫，不等於 SQL Server）；前端用 `agent-vue-build.sh` 驗證能建置（vite build 通過，未在瀏覽器實際操作）。

已勾選項的證據：必填且存在、僅啟用中公司可選、草稿與已退回可改其他狀態不可改、送簽時公司已停用被擋、送簽後停用不影響核准、列表依公司篩選與回傳簡稱／詳情回傳統編與啟用狀態、被出差單引用的公司不可刪除（仍可停用）、種子資料先建公司，都有服務層測試（紅燈先行：新增、編輯、送簽、列表、引用檢查各先看到編譯或執行期失敗再實作）。

未勾選項與原因：

- **資料表與既有資料庫腳本（`docs/sql/出差單公司欄位.sql`）**：資料庫專案的資料表 SQL、實體與 DbContext 已同步；腳本比照領料單那份寫成可重複執行（加欄位允許空值 → 用「預設公司」回填 → 改必填 → 加索引與外鍵），但沒有在 SQL Server 執行過，需使用者在真實資料庫驗證，並確認先執行過 `公司資料表.sql`。
- **前端（編輯頁公司下拉、列表欄位與篩選、詳情顯示統編）**：已實作（新單且只有一間啟用中公司自動帶入；編輯時原公司已停用顯示「（已停用）」並提示送簽前改選；列表加公司欄位與公司篩選），但只驗證能建置，沒有在瀏覽器實際操作，需使用者手動驗證。

偏離 ticket／spec 的決定：

- 編輯時「維持原本已停用的公司」允許儲存其他欄位，「改選一間已停用的公司」被擋；送簽時才擋停用公司（與 ticket 02 相同，錯誤碼 `FieldValueIsInvalid`，訊息「所選公司已停用，請改選其他公司」）。
- 詳情與列表額外回傳 `CompanyIsActive`，讓前端標示「（已停用）」。
- 列表的公司篩選下拉只列啟用中的公司（沿用填單選單 API，避免要求公司檢視權限）；已停用公司的歷史出差單仍會顯示在列表，只是不能用該公司篩選。
- 出差單沒有匯出功能，不需要加公司欄位。
- 重疊檢查與簽核流程未改動，既有出差單測試全部維持通過。
