# 領料單的簽核動作由模組自己的端點處理，且核准與扣庫存同一交易

簽核引擎在最後一關核准時會先把「核准」存檔，模組才接著改庫存，進貨單因此可能出現「已核准但庫存沒更新」；通用 `ApprovalController` 又能對任何單據直接執行簽核動作而繞過模組邏輯。領料單決定：送簽、核准、拒絕、撤銷、作廢五個動作都走領料單自己的端點，在領料單服務內以單一資料庫交易包住「引擎動作 + 單據狀態 + 庫存增減 + 異動紀錄」，並讓通用 `ApprovalController` 對領料單的這五個動作回錯誤。

## Considered Options

- **讓引擎呼叫 Handler 鉤子（`OnApprovedAsync` / `OnVoidedAsync`，並補拒絕/撤銷鉤子）**：架構較乾淨，通用端點也能正確運作；但需重構共用的簽核引擎，牽動請假與公文，範圍過大，暫不採用，列為後續改善。

## Consequences

- 領料單的寫法與進貨單不一致，這是刻意的；進貨單的同類問題（非原子、可被通用端點繞過）列為已知問題，未在本次修正。
- 之後若改採鉤子方案，領料單的五個端點可退化為薄層。
