# 出差單狀態由出差單自己維護，簽核動作走出差單專屬端點

簽核引擎只記錄簽核紀錄，不維護單據狀態：拒絕與撤銷沒有鉤子，撤銷與作廢都把紀錄標成 `GetRevoked`，光看簽核紀錄分不出「已退回」與「已作廢」；請假單的 `ApprovalStatus` 欄位也從未被更新。出差單要有明確的草稿、簽核中、已核准、已退回、已作廢五個狀態，決定比照領料單（ADR-0001）：出差單自存 `Status`，送簽、核准、拒絕、撤銷、作廢五個動作走出差單自己的端點，在服務內以單一交易包住「引擎動作 + 單據狀態」，並讓通用 `ApprovalController` 對出差單的這五個動作回錯誤。出差單核准不改動庫存或其他資料，採用此做法的理由是狀態一致，不是原子扣庫存。

## Considered Options

- **沿用通用簽核端點，狀態由簽核紀錄推導（比照請假單）**：不必寫專屬端點；但無法區分撤銷與作廢，通用端點可繞過出差單邏輯，狀態不可靠。
- **讓引擎補上拒絕、撤銷鉤子**：架構較乾淨，通用端點也能正確運作；但需重構共用簽核引擎，牽動請假、公文與領料單，範圍過大，與 ADR-0001 同樣暫不採用。

## Consequences

- 出差單的寫法與請假單不一致，這是刻意的；請假單沒有單據狀態的問題不在此處理。
- 日後若引擎補上鉤子，出差單與領料單的專屬端點可一併退化為薄層。
